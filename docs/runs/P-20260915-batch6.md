## Design decisions (lead)

- **PDC placement:** compensation is a per-track `DelayNode` between the
  panner and the destination; the master chain sits downstream of the sum
  and needs no per-track term. `setTargetAtTime(…, 0.01)` only (the DJ's
  time constant) — no value jumps. Inert VST3 counts 0 live (T09a's
  `counted:false`) — the documented live/bounce gap; render trim, meters
  and automation-read offsets are step 3.
- **Renderer adoption is measured, not argued:** T11b keeps the old bodies
  behind a `LEGACY` switch until a browser A/B per renderer is within
  1e-6 (1e-4 is the stop line), then deletes them. `git stash` is
  forbidden in the shared worktree.
- **Recording engine first, wiring second:** `startSec` is stamped at the
  recorder's `onstart`, not at the call — that is D13's fix — and the
  engine is browser-API-free behind injectable deps so the takes model is
  testable before any UI exists.
- **Gesture boundary at the widget:** batch 5's window-listener + idle
  machinery in `WaveformEditor` was the fallback for a widget with only
  `onChange`; the tracker lives in `lib/gestureTracker.ts` so the rule
  (one start before the first change, one end after the last, for pointer,
  key and wheel) is pinned without a DOM.
- **Routing in the mixer:** buses and sends tap post-pan/post-comp;
  `muteGain` stays pre-FX (a lead decision — tails die on mute, as today);
  a malformed graph falls back to every-track-to-master and logs, never
  silence; sidechain waits for `sideInput` on `RackEffectInstance`; the
  offline bounce keeps rendering straight to master this batch.
