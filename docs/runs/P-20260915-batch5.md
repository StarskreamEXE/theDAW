## Design decisions (lead)

- **Modes** follow Tracktion's `AutomationRecordManager` behaviour (GPL —
  design only, nothing copied): touch punches out on release, latch holds the
  released value until stop, write seeds every enabled lane at play start and
  demotes itself to latch on stop. A hold writes forward by *overwriting*
  (`writeSpan` removes the points it passes over), so a pass leaves no stale
  breakpoints inside it.
- `automationWrite: boolean` stays as a derived field kept in sync by the
  store so batch-4 consumers keep compiling; T08b switches them and the field
  is removed in a later cleanup.
- **Curve** is per point and shapes the segment that starts at that point
  (`AutomationPoint.curve ∈ [-1, 1]`, 0 = linear). The shape function is
  pinned by seven laws (endpoints, identity at 0, monotonic, sign, mirror
  symmetry) rather than by a formula, so drawing (T08c) and playback (T08b)
  agree by construction — both sample `interpolatePoints`.
- Live curved segments use `setValueCurveAtTime`; T08b must verify the
  overlap constraints through the doc chain, not from memory.
- §3.8/§3.6/§3.5 ship their **pure, testable model** first, each in a new
  file, so the engine-touching steps (live PDC, liveMixer routing rebuild,
  renderer adoption + job queue) can be ticketed against verified exports.
