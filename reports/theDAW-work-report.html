Agent 2 — investigated (read-only)
•

Looked into the DJ harmonic-mixing / "auto-DJ compatibility" question  RECON ONLY

Findings it reported back:

  • "z auto dj" is not a framework — it's a Python virtual environment used to run one harmonic-feature extraction script (the madmom key/Camelot/downbeat extractor). Not a mixing engine.
  • The ingredients a DJ auto-mixer needs are already computed per track: Camelot-wheel codes + BPM + key/mode/confidence.
  • The gap: nothing consumes those for actual track-to-track matching — there's no engine that answers "what can I mix into this next." A harmonic_neighbors field (same/adjacent Camelot + relative key, within a ±6% BPM window) is specced but not built.
  • It offered to dig further into how that data is wired — read-only, nothing built.

How this touches theDAW: theDAW already shows Camelot/key (harmonic chip + frontend/src/lib/camelot.ts) and its set-builder orders by key+BPM, but the live Auto-DJ plays sets in order — it doesn't pick the next track by harmonic compatibility. That engine is the open opportunity Agent 2 surfaced.
